What the app does

A kanban-style board manager that lets users organise work into boards, lists, and cards with rich metadata — all draggable and editable in real time.

📋

Board Management

  • Create, rename & delete boards
  • 6 preset background colour themes
  • Dashboard grid view of all boards
  • Per-user ownership & isolation
🗂️

Lists

  • Unlimited lists per board
  • Drag-and-drop horizontal reordering
  • Rename inline
  • Delete with full cascade
🃏

Cards

  • Create cards with title & description
  • Move cards between lists via drag-and-drop
  • Vertical reordering within a list
  • Inline title editing on the tile
🔐

Authentication

  • Register with name, email & password
  • Secure bcrypt password hashing
  • Persistent sessions via refresh tokens
  • Auto logout on expiry

Card detail features

📝

Descriptions

Rich-text descriptions on every card, editable directly in the detail modal with save/cancel controls.

📅

Due Dates

Date-picker with colour-coded badges: red for overdue, yellow for today, grey for future dates.

🏷️

Labels

Coloured labels with custom text — choose from 6 preset colours (green, yellow, orange, red, purple, blue). Multiple labels per card.

✅

Checklists

Named checklists with multiple items, checkbox completion tracking, and a progress bar that turns green at 100%.

UX highlights

⚡

Optimistic UI

Changes appear immediately. On server error the UI rolls back automatically — no loading spinners for common actions.

🔔

Toast Notifications

Context-aware toasts for success and error states via react-hot-toast — never leaves the user guessing.

🛡️

Protected Routes

Unauthenticated users are redirected to login. Sessions persist across page refreshes via token refresh.

Auth & session flow

1

Login / Register

Server returns a short-lived access token (15 min) in the JSON body and sets a refresh token (7 days) in an httpOnly cookie.

2

Requests

The React AuthContext stores the access token in memory. Axios attaches it as a Bearer header on every request.

3

Token refresh

On a 401, the Axios response interceptor silently calls /api/auth/refresh (cookie is sent automatically), gets a new access token, and replays all queued requests.

4

Logout

Server clears the cookie; client clears the in-memory token. Both sides are invalidated in one request.

All relationships use cascading deletes — deleting a Board removes all its Lists, which in turn removes all Cards, Labels, Checklists, and ChecklistItems. Drag-and-drop order is stored as a Float; reordering inserts a card at the midpoint (before + after) / 2, so no full-table re-index is ever needed.

⚠️

Test database safety

The server and E2E test suites truncate all tables between runs. They must point at a dedicated test database configured in server/.env.test. Never run these tests against a development or production database.
